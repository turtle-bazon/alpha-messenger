# #81 — Аудио и видео звонки (1-на-1)

Реализовать звонки аудио/видео между двумя пользователями, как в Telegram Desktop.

## Объём v1
- Только direct-чаты (1-на-1). Групповые звонки — отдельная задача.
- WebRTC P2P для медиа; сигналинг через существующий WS (транзитные события,
  как typing — мимо outbox).
- Входящий вызов: оверлей с именем/аватаром, принять (аудио/видео), отклонить.
- Исходящий: «Вызов…», после соединения — таймер, mute микрофона, вкл/выкл
  камеры, сброс. Для видео — удалённое видео + локальное PiP.
- Таймаут исходящего (~45с без ответа → отмена). Занято (busy) при втором
  входящем во время активного звонка.

## Сервер
- Новый WS-клиентский тип `call`: `{ type:'call', to: userId, data }`.
  Сервер проверяет, что `to` — участник общего с отправителем direct-чата,
  и пересылает `sendTransient(to, { type:'call', payload:{ from, ...data } })`.
- Без изменений БД. Пропущенные вызовы как системные сообщения — v2.

## Клиент
- `api/ws.ts`: `sendCallSignal(toUserId, data)`.
- `chats/useCall.ts` — менеджер звонка: RTCPeerConnection (STUN Google),
  getUserMedia, offer/answer/ICE через WS, состояния idle/outgoing/incoming/
  active, таймауты, busy.
- `chats/CallOverlay.tsx` — полноэкранный оверлей (входящий/исходящий/активный).
- Кнопка звонка в заголовке direct-чата (аудио/видео).

## Тесты
- E2E: два контекста с fake-media флагами; A звонит → B видит входящий →
  принимает → оба в active → A сбрасывает → оверлеи закрылись.
