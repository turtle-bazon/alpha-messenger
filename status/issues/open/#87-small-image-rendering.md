# #87 — Рендер маленьких изображений

Медиа-пузыри не должны ограничиваться натуральной шириной inline-превью
(~320px): на широком чате фото выглядят мелко. Как в Telegram — картинка
занимает стандартную медиа-ширину, соотношение сторон сохраняется.

## Проблема
`.bubble--media` — shrink-to-fit: `width:100%` у img разрешается в ширину
thumb'а (≤320px по THUMB_MAX_DIM), плюс был `min-width:280px`. Итог —
большое фото едет в пузыре ~320px независимо от размера окна.

## Решение
- `mediaStyle(w,h)` в Conversation.tsx (#87): бокс из метаданных вложения —
  `width = w·min(480/w, 480/h)`, `aspectRatio: w/h`; CSS `max-width:100%`
  сжимает на узких экранах, высота следует соотношению. Константы
  MEDIA_MAX_W/H = 480.
- CSS `.bubble-image img`: убраны `min-width` и `width:100%`; для легаси без
  метаданных — натуральный размер с капом `max-height:480px`.
- Видео/стикеры не тронуты (вне скоупа тикета).

## Тесты
- `e2e/helpers/media.ts` — минимальный PNG-энкодер (node:zlib) для фикстур
  с точными размерами + хелпер sendImage.
- `image.spec.ts`: 640×400 → бокс ровно 480×300 у отправителя и получателя;
  100×80 → 480×384 (апскейл до стандартной ширины). Прогнать на стеке
  run/dev (здесь БД нет).

## Приоритет
high (тикет Focus #53)

## Уточнение (#75, 2026-08-21)
На старых Android WebView без поддержки CSS aspect-ratio боксы могли
рендериться исходными 480px и обрезаться overflow:hidden («не помещается»).
Теперь mediaStyle задаёт width И height явно (object-fit:contain страхует
узкие экраны) — размер больше не зависит от aspect-ratio.
